# 开源自动剪辑方案与实际接入范围

已核查 GitHub 来源：

| 项目 | 能力 | 当前处理 |
| --- | --- | --- |
| [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) | 通过画面变化检测镜头边界 | 已接入 ContentDetector，scenedetect 0.6.7.1 + headless OpenCV，CPU 运行 |
| [TransNetV2](https://github.com/soCzech/TransNetV2) | 神经网络镜头切分，提供 PyTorch 推理 | 已查阅，未安装权重；本阶段不额外引入 PyTorch |
| [CLIP](https://github.com/openai/CLIP) | 图像与文本相似度，可做脚本/关键帧粗匹配 | 已查阅，尚未接入；相似度不等于完整视频理解 |
| [Qwen2.5-VL](https://github.com/QwenLM/Qwen2.5-VL) | 多模态画面与视频理解，可用于按脚本选段 | 已查阅；项目文档已指向后续 Qwen3-VL。需独立推理资源或兼容云 API，当前未接入 |

PySceneDetect 是开源算法库，不是生成模型，也不会判断商品卖点。选择它是为了先在用户当前 CPU/512MB 免费服务上提供可执行的镜头检测；并未证明所有上传视频都在此资源配置内完成。视觉语言大模型参数与运行时需要远超当前可用内存的资源，不能把仓库可下载当作免费服务器能运行。

## 当前执行流程

1. 为检测制作最长 180 秒、8fps、256×144 范围内保持比例的低分辨率临时代理视频；限制 FFmpeg/OpenCV 线程，降低资源需求。
2. 用 ContentDetector 检测切镜点。它更适合硬切，渐变转场、闪光或曝光变化可能漏检/误检。
3. 从不同镜头按原时间顺序选择片段，每段最多约 2.5 秒，并略过各镜头的部分首尾。目标时长是上限，短源视频或镜头数量不足时不重复补齐。
4. 单一镜头回退为按时间规则取多个片段。若画面本身基本不变，视觉变化仍可能不明显；不会凭空产生新镜头。
5. FFmpeg 实际切割、裁切竖屏并拼接。输出保留原有 BGM 选择行为：官方曲库模式不带音乐，本地授权音乐模式添加所选 BGM。当前不保留素材原声，不生成配音或字幕。
6. 保存任务旁的 `*-edit.json`，记录选择方式、源素材、起始时间、片段长度、输出时长及音频状态；团队任务提供摘要与报告链接。

“顺序拼接”保留旧行为；“节奏剪辑”跳过检测，仅按时间取材；默认“镜头检测剪辑”。目前脚本只存为简报，并未参与上述选择。

## 验证

真实集成测试构造 12 秒、三个不同颜色镜头的测试视频，检查检测边界位于约 4 秒、8 秒；输出为约 7.5 秒、三个镜头的剪辑。再次解码成片帧，确认三个原始镜头确实出现在输出中。单镜头测试检查回退会产生不连续源时间段，音乐测试继续验证音轨、音量、循环与淡出。测试不等同于商业商品片质量评估。

## 后续语义剪辑

真正根据脚本选择“商品特写/使用演示/口播”等片段，需要视觉语言模型分析关键帧，并把结果约束成有效剪辑时间轴，之后由 FFmpeg 执行。目前缺少可用推理资源或 API 凭据，未宣称已实现。可优先使用云端多模态 API按量验证，再决定是否自托管开源权重。
